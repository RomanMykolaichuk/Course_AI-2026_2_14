# Data directory

The repository uses four data zones. Large or frequently changing files are excluded from Git; this directory mainly preserves structure and documentation.

## raw/

Immutable source snapshots exactly as acquired from external sources.

The primary acquisition command creates:

```text
data/raw/piterfm_massive_missile_attacks/<YYYY-MM-DD>/
├── missile_attacks_daily.csv
├── missile_attacks_daily.csv.meta.json
├── missiles_and_uavs.csv
├── missiles_and_uavs.csv.meta.json
└── snapshot.json
```

Other source snapshots may follow their own documented subdirectory structure.

Do not edit raw files manually. Store acquisition metadata in a sidecar `*.meta.json` file when a snapshot is used in an experiment.

## interim/

Source-specific parsed/cleaned outputs which are not yet canonical.

Examples:

- parsed timestamps;
- normalized weapon names;
- extracted target-region mentions;
- deduplicated source records.

Files in this zone may still follow source-specific semantics.

## processed/

Canonical analytical data generated by project code.

The primary loader creates:

```text
data/processed/primary/<snapshot-date>/
├── attack_events.csv
├── attack_event_regions.csv
└── manifest.json
```

Future processed outputs may include region/time-bucket ML feature tables.

Only reproducible code-generated outputs should be placed here.

## external/

Stable reference/enrichment files.

The geoBoundaries acquisition command creates:

```text
data/external/geoboundaries/<boundaryID>/
├── UKR_ADM1.geojson
└── metadata.json
```

For the 2026-09-22 baseline this resolves to `UKR-ADM1-14850775`.

Other examples:

- region lookup tables;
- small reference dictionaries.

Large weather extracts such as ERA5 should normally remain outside Git and be recreated from documented acquisition code.

## Recommended snapshot naming

```text
<source>_<dataset>_<YYYY-MM-DD>[_vVERSION].<ext>
```

Examples:

```text
kaggle_piterfm_missile_attacks_daily_2026-09-22.csv
geoboundaries/UKR-ADM1-14850775/UKR_ADM1.geojson
```

## Metadata sidecar

Recommended:

```text
<data-file>.meta.json
```

The sidecar should record:

- source name and URL;
- acquisition timestamp;
- release/version;
- license or terms URL;
- acquisition method;
- SHA-256 checksum;
- row count/file size;
- filters applied.

See [Data Governance](../docs/data_governance.md).

## Canonical model

The canonical model is relational because a source attack row may refer to several regions or to a broad target such as a direction or all of Ukraine.

Core entities:

```text
attack_events
      │
      ├──< attack_event_regions >── regions
      │
      ├── optional alert_intervals
      └── optional weather_observations
```

Do not force every attack row into one `region` field.

The complete schema and field definitions are documented in [Data Dictionary](../docs/data_dictionary.md).

## MVP source precedence

1. attack observations: Kaggle `piterfm/massive-missile-attacks-on-ukraine`;
2. GIS boundaries: geoBoundaries `gbOpen` ADM1;
3. optional weather: ERA5;
4. alerts: only when a reproducible historical archive is available;
5. ACLED/UCDP: independent validation/backfill experiments.

See [Data Sources](../docs/data_sources.md).
